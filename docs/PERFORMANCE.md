# Производительность

## Что измеряется

ASIJI 0.9.3 сохраняет качество RGB-кадров и точные цвета. Orbit кэширует
радиус и угол каждого пикселя до изменения размеров. Wave рассчитывает
координаты двух каналов один раз на столбец, а не для каждой строки.
Кэш Orbit занимает 8 байт на пиксель: около 1,07 МиБ для сетки 500×280.
У Bars этого кэша нет; у Wave буфер занимает 8 байт на столбец.

Тест сравнивает новый рендерер с формулами версии 0.9.2 в одном процессе.
Проверка совпадения RGB охватывает три стиля, все палитры, маленькие и обычные
размеры, разные чувствительность, число полос, пропорции пикселей и уровни сигнала.
Эталон находится только в тестах и не включается в исполняемый файл плеера.

## Windows: замеры 24 сентября 2026

AMD Ryzen 9 9900X, Windows, Rust 1.98.1, release-сборка, сетка 500×280 RGB-пикселей, 10 кадров прогрева и пять серий
по 200 кадров. Ниже медианы чередующихся замеров новой и эталонной реализации:

| Стиль | 0.9.2, мс/кадр | 0.9.3, мс/кадр | Ускорение |
|---|---:|---:|---:|
| Orbit | 3,142 | 0,692 | 4,54× |
| Wave | 0,739 | 0,560 | 1,32× |

Это время **отрисовки RGB на CPU**. Оно не включает чтение аудио, FFT,
кодирование ANSI, передачу в терминал и фактический показ на экране.
Рост общего FPS в такое же число раз не обещается: он ограничен выбранной
частотой кадров и скоростью конкретного терминала.

Отдельный контрольный замер текущего кодировщика видео: синтетический
FFmpeg testsrc2 640×360/60, 180 кадров, CPU-декодер, 500×140 ячеек HD —
около 0,33 мс подготовки ANSI на кадр. Этот код в 0.9.3 не изменён.

## Проверка полного сеанса на Windows

Две версии запущены по три раза через ConPTY: синтетический стереотон 330 Гц,
500×94 терминальных ячейки HD, 60 FPS, громкость 0, по четыре секунды после
старта воспроизведения. Медианное время подготовки кадра (чтение PCM, FFT,
отрисовка RGB), мс/кадр:

| Стиль | 0.9.2 | 0.9.3 |
|---|---:|---:|
| Orbit | 2.020 | 0.479 |
| Wave | 0.569 | 0.425 |

Обе версии выдали 239–240 кадров за четыре секунды: частоту ограничивает
настройка 60 FPS. Выигрыш здесь — меньше работы CPU, а не увеличение FPS.
У Wave передача ANSI заняла примерно 3–4 мс/кадр — больше подготовки RGB.
ConPTY не измеряет время показа кадра графическим окном терминала.

## Повторить

```sh
cargo test --release --locked pixels_match_reference
cargo test --release --locked benchmark_visualizer -- --ignored --nocapture
```

Строки `VISUAL_BENCH` содержат все пять замеров для сеток 160×90 и 500×280.
`reference_ms` — эталон 0.9.2, `draw_ms` — текущий рендерер.
CI запускает сравнение и бенчмарк на Windows и Linux. Виртуальные машины CI
не подходят для обещаний о скорости Kitty, Konsole или Windows Terminal:
производительность самих терминалов нужно измерять отдельно.

Для сеанса с вашим файлом используйте `--profile report.json --profile-seconds 10`.
`render_ms` включает подготовку ANSI; `decode_queue_ms` включает подготовку
кадра визуализатора, а для видео — ожидание очереди, без работы FFmpeg-процесса.
`terminal_write_ms` измеряет отправку данных, а не завершение их отображения.
Не сравнивайте первый запуск с подготовкой аудиокэша с повторным запуском.

## Проверенные варианты

| Изменение | Результат | Решение |
|---|---|---|
| Кэш геометрии Orbit | 2,93 → 0,64 мс в отдельном замере | Оставлено |
| Координаты Wave по столбцам | 0,74 → 0,55 мс | Оставлено |
| Специализация общего цикла по стилю | Небольшая дополнительная разница между запусками | Убрано: выигрыш не отделён от разброса |

Порог скорости не является тестом корректности: нагруженный CI может быть
медленнее. Побайтное совпадение картинки проверяется независимо от таймингов.
